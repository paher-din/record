## 5. Record 专属设计系统候选骨架

以下除 Android 平台约束外均为 **Record 设计提案**。实际色值、字重、圆角、图标和动效在方向选定后作为 D-SYS 候选一次完成，不分散写死到页面。

### 5.1 ColorScheme

按 `MaterialTheme.colorScheme` 语义配置两套完整 scheme，不以 Hex 数量代表设计品质。每个方案先建立 `primary/onPrimary/primaryContainer/onPrimaryContainer`、`secondary`、`tertiary` 四色对；同时补齐 error、surface tiers、outline、inverse、scrim 和适用 fixed roles。`background/onBackground` 如所选库仍需要则与 surface 主角色一致，不另生冲突层。

| 角色组 | 使用原则 |
|---|---|
| Primary | 主要动作、当前选择与品牌；不能收入/支出都只靠颜色区分 |
| Secondary | 辅助控件与低强调区域；不把所有信息染成彩色卡片 |
| Tertiary | 小范围关系/任务强调，不与危险、成功混淆 |
| Surface lowest/low/container/high/highest、dim/bright | 按内容/层次分配 tone；不手工加 elevation 主色 overlay |
| On-surface/variant | 普通字与辅助字均实测；半透明降低对比不可随意采用 |
| Error / warning / success | 必须文字+图标；warning/success 是扩展语义，不滥用 tertiary 冒充所有状态 |
| Outline / variant | 前者承担必要可见边界；后者只装饰分隔 |
| Inverse / scrim | Snackbar、暂态覆盖；scrim 不用于美化整页 |

浅深主题均独立设计，非简单反相。默认品牌静态色；动态取色若以后提供，作为明确选项，须重测语义/对比。文本目标普通 ≥4.5:1、大字/必要非文字 ≥3:1；这是验收目标，不代表生成图已经达标。最终颜色表必须附脚本计算的实际色对与状态背景，不引用“角色配对必然全部合规”。

### 5.2 Typography / Shapes / Spacing

| 项 | 候选规则 |
|---|---|
| 文字角色 | `display` 只用于少量有意义焦点，`headline` 页面语境，`title` 内容摘要，`body` 正文/输入，`label` 控件；不逐页独立调字号 |
| 起始字号 | 页面标题 28/36sp、内容标题 20/28sp、正文/输入 16/24sp、辅助 14/20sp、主要金额 36/44sp；需要大展示时 48/56sp。均为待实测起点，不是官方强制值 |
| 数字 | 金额基线和小数对齐，tabular numerals，保留正负/币种；长金额重排而非压到不可读；编辑保留原始十进制输入 |
| 字体 | 先验证系统中文与数字字形，品牌字体只用于确有收益的位置；若引入开源字体需核 LICENSE/子集/包体，不在线动态下载字体，不仿造专有字体 |
| Shapes | 按任务区分信息容器、动作、浮层、角色；候选 0/4/8/12/16/20/28dp 与 full，不要求每页同形；不把花形用于文字大容器 |
| 间距 | 4/8/12/16/24/32dp 作为候选节奏，正文边距 20dp、窄屏 16dp；可读内容优先于机械网格 |
| 密度 | 金额短行与 Note 长行有不同内距；内容多不等于缩小所有文字和目标 |

支持系统字体放大和非线性字号缩放，不锁固定行高/卡片高度，数值用 sp、布局用 dp。2× 字体时允许折行和双列退化。

### 5.3 Surface / Elevation / Iconography

候选 elevation 层级：内容 0dp、轻抬升动作 1–3dp、Sheet/Dialog 6dp 作为原型起点；优先 tone 与遮挡关系，阴影只解释高度。材质实验限定到一个主场景，不让每个表面变磨砂玻璃。昂贵材质永远有相同几何与层次的实色替代。

图标从一套一致的 Material Symbols/自绘资产族挑选，24dp 起点、必要时 20dp；触控面仍 ≥48dp。用字重、光学尺寸、填充选择态形成一致规则。装饰图标不重复朗读，独立动作有名称和状态。收入/支出、Note、关联是业务类型，不靠颜色或随机形状单独编码。

### 5.4 Navigation / States / Haptics / Accessibility

- 导航按真实目的地决定，记账/写笔记是动作而非 tab。候选可比较单主流+筛选与多入口，但不能为了填满 3–5 个底部项制造统计/搜索功能。窄屏单列，大屏列表/详情/上下文可双栏；按可用空间和姿态重排，不按设备名分支。
- 系统 Back、键盘、TalkBack 与可见返回一致；Back 先处理 IME/已获批离开语义。返回恢复筛选、日期锚点和位置。跨关联返回不重置整个时间线。
- 组件必须覆盖 default、pressed、focused、selected、disabled、loading、empty、error；异步操作额外区分 conflict、unknown、interrupted、revoked。disabled 不只是透明变淡，状态文案仍可读。
- Haptic 候选：分类选择/有效拖动停靠轻触一次；确认持久成功可单次反馈；提交未知/失败不发成功触觉。遵守系统触觉偏好，低能力设备自然降级，不每个数字按键都强震、不为动画循环震动。
- TalkBack 有金额方向/币种/日期/关联数，助手有打开/隐藏/移左/移右可见替代；点击目标至少 48dp，不把拖动作为唯一操作。
- 状态变化使用适当 semantics/live region，不每个 token 或自动保存中间态朗读；错误恢复动作可找到，不抢输入焦点。支持深色、大字号、增加对比、键盘、减少动态效果。

## 6. Motion System：独立设计重点

### 6.1 动态语法与权威边界

把空间运动、颜色/透明度、事实状态分开。Expressive 的 spatial spring 可用于位置/尺寸/形状；effects 无 overshoot。数值与编排是 Record 候选，不把“统一 200ms 淡入”当完整 Motion 系统。交互中断后从当前速度/位置继续，不队列播放过时状态。

| 场景 | 候选编排与起始参数 | 中断 / 减少动画 / 事实要求 |
|---|---|---|
| 页面进入退出 | 同层 160–220ms fade-through；详情容器 240–320ms shared bounds；小幅 8–16dp 位移 | Back 可预测、反向连续；减少动态时即时/≤80ms 透明度；无入场封锁 |
| 列表插入/移位 | stable typed id；可见新项 180–240ms placement，轻透明度；不整屏重播 | 已持久化才加入正式事实；用户回看旧日期不强制拉回顶部 |
| 删除 / 撤销 | Note 确认软删除后收拢；撤销恢复同身份与原时间 | 动画不触发删除/恢复；失败保留真实项目，减少动画即时变化 |
| 卡片/关联展开 | 200–280ms 边界展开或 spatial spring；只绘当前可见关联 | 保持锚点，不对每行全量重测；内容立即可达，大字体用常规展开 |
| 金额输入 | 输入文本/光标立即更新，变化数字可做 80–120ms 短淡变 | 不滚动模拟尚不存在的中间金额；不朗读装饰副本；减少动画纯文本 |
| 分类选择 | 状态容器形状变化 120–180ms 或 fast spring，字/颜色不回弹 | 选择立即生效，不等弹性收尾；文本保持不动 |
| 保存状态 | 按下即时响应；持久成功后 120–180ms 状态替换，可单次触觉 | 不强制成功停留延时；unknown 进入核查态，没有对勾/绿色完成 |
| Note 阅读/编辑 | 编辑器保持同一文本/选择 owner，工具栏 100–160ms 出入 | 不用整块 AnimatedContent 重建输入框；IME/光标优先 |
| 助手拖动/停靠 | Animatable + 手势速度，停靠候选 damping .85/stiffness 500 | 是项目候选值；不覆盖其他业务触控；提供按钮替代，减少动画即时停靠 |
| Agent 工作对象 | 当前真实步骤短切换；引用到提案可单次 220–300ms 轨迹显现 | 无事件只说“处理中”；不捏造推理/工具或百分比，隐藏时暂停绘制 |

空间 spring 初始可用 Expressive reference 的 default `.8/380`、fast `.6/800`、effects `1/1600` 或 `1/3800` 做对照；**不声称所有组件必须按该数值实现**。这是对 reference 数值的实验输入，最终按实际大小/速度/settling 与可访问性选取。

颜色/透明度可用受控无回弹 spring 或 `CubicBezierEasing(0.2,0,0,1)` 作为 Record 过渡候选；位置与尺寸优先可打断 spring。固定时长用于编排预算，不能把 spring 写成精确持续 N ms。不将 Web cubic-bezier 近似表当 Compose 弹簧实现。

### 6.2 动态降级

读取实际 Compose/system duration-scale，scale=0 时空间动画、形变、视差、循环装饰和 shader 全停，直接展示最终状态；保留必要文字反馈。自写 frame loop/shader 不保证自动响应系统设置，必须显式接入。应用失焦/面板隐藏/相关状态结束立即暂停；恢复不补播已错过动画。不用把 MotionScheme 换成 Standard 冒充完整减少动态支持。[Compose MotionDurationScale](https://developer.android.com/reference/kotlin/androidx/compose/ui/MotionDurationScale?authuser=44)

## 7. 五个重点页面的独立方案

### 7.1 首页

先解决“一步开始记账/Note、轻松重新进入内容、随时可回看”。首页可以是捕获入口、内容索引、消息式记录或继续编辑工作台；无需同时堆出完整历史。回看仍提供既有连续浏览能力。让真正的内容成为视觉焦点：金额与文字不同排版，日期为定位，不一定成为巨型装饰。图形可表达真实记录分布或关联，不画虚构余额趋势；动态余额卡片因 V1 没有余额模型，本轮不采用。需要精确汇总时只呈现已授权查询的范围和结果，不扩展统计大盘。

候选布局比较：收件箱式内容索引、明确模式的消息式捕获、大输入区、最近对象继续编辑，以及连续流/账页等已有候选。不是同样卡片换主题。首屏按其主任务评估：输入首页看模式/焦点/动作，索引首页看重入入口，回看页看内容密度；不再用“必须放三条历史”统一规定所有首页。创建入口始终可达，不藏在滚动手势后。

消息式捕获需明确“笔记 / 记账 / 问 AI”的当前模式、发送/保存的结果和失败恢复。日常记录不是与虚构人物聊天；历史业务记录可用结构化 receipt 表达，但不能用已读勾当提交依据。记账模式仍进入确定性表单或明确提案确认，文本发送不授予模型业务写入权。用户只想写 Note 时不能默认请求模型。

### 7.2 记账与交易编辑

页面以收入/支出、金额、发生时间为前半部，分类/账户/说明按阅读优先级展开；分类仍至多一个可选项，默认账户不暗示余额。可比较原生 IME 与自定义数字面板；**自定义键盘不是默认选项**，必须证明选择/粘贴/小数/辅助输入/无障碍成本值得。两种路径输入均立即可用。

数字动画只在展示层，Long 整数分和原始 decimal 文本不受动画污染；输入 `0.`、尾零、中文粘贴、删除/选中不跳光标。分类选择通过 connected shapes/颜色与触觉表达选中；不做费时转盘。

保存状态区分记录与草稿：未保存、草稿持久中/失败、记录提交中/失败、版本冲突、结果未知、成功。成功后通过一个连贯转场回到原时间线/同身份记录；失败保留字段，未知先按稳定身份核查，不能新建第二笔。D5 离开/继续/显式放弃按既有合同，不为了顺滑动画跳过。

### 7.3 Note 阅读与编辑

无标题纯文本，用首段原文摘要承担列表辨识，不新增标题字段、富文本/Markdown 或附件。阅读页以文本宽度、行距、日期和关联收支为主要层次；编辑工具栏只放真实功能，不能用假格式按钮填空间。

阅读到编辑保持位置与光标上下文，工具栏可短变换，文本不要整块缩放/弹入。保存状态与服务 inputRevision 对齐：旧回执不宣布新文本已保存，失败/冲突保留本地正文，可比对最新版本；不静默替换。清空正文不能隐式删除。删除/撤销/恢复是原生专用流程，恢复同身份、发生时间和原关系，不插成“今天的新笔记”。

### 7.4 时间线与关联

时间线有条件成为产品识别核心，但不等于每条都画一根彩色竖线。日期、时间、金额、正文、关联各占稳定排版位置；Finance 短而准、Note 让阅读发生，类型由文本/图标/结构共同辨认。

优先实验“日期快速定位＋稳定回看”和“局部关联展开”：拖动时间定位时展示实际目标日期，松手定位；保留日期选择器/今天按钮，避免仅手势可用。关联轨迹只在主动展开的一小组可见记录之间绘制，不能在整个 LazyColumn 上常驻绘制关系网。跨日关系点开对端，返回恢复原锚点；不改变排序来把相关内容强行挤在一起。

分页使用 stable typed key、确定性排序与业务游标；contentType 区分记录类型，停止滚动才做必要低频反馈。不对快速滑动逐条播放入场/视差；列表下方有已加载内容时，append 失败保持内容和重试，不变空白。关联保存保持增量意图、端点版本、隐藏关系及全批原子失败语义。

### 7.5 AI Agent：任务台，而不只气泡

保留用户可见会话与输入，让结果组织为“任务说明 → 真实处理状态 → 引用对象 → 结果/提案”。四种输出有各自组件：Answer 为可读回答加范围与引用；Navigate 为校验后入口；ClarificationNeeded 为问题和补充动作；ProposalReady 为明确未提交的操作清单。

候选 Task Surface 不取代 Koog Loop，不暴露模型隐藏推理。可以展示真实读取/查找/准备提案的工具事实；无可靠事件时只展示 Running/处理中。临时步骤不加入新的持久 trace 表，不把运行协议原始参数/私有正文倾倒成 UI。跨进程只以 Room 历史/Interrupted 等权威状态重建，不播放虚构的工作回放。

Proposal 中突出**影响对象和前后变化**：新增收支金额/日期/账户/分类、Note 原文、Link/Unlink 两端；同一逻辑块内可折叠细节。状态“待确认，尚未写入记录”与主动作同屏。检查/编辑只改 Proposal revision，绝不触发原生 Note autosave、不消费 D5；只有当前显示版本的原生确认提交走 A/B。

Applied 才转换为“已保存”和真实记录入口。Pending/OutcomeUnknown 明示核查、锁重复；版本/代际/目标冲突保留提案并重审，不用漂亮成功动画覆盖失败。收起面板不取消 Run，不默认再弹聊天确认。角色外观可以完全重做，但 App 内全局可隐藏/移动/贴边、Bottom Sheet 和授权边界仍受冻结功能合同约束；若要替换它们，应另行获得产品合同变更决定。

### 8.2 候选技术表

| 技术 | 本项目适合用途 | 实施条件 / 退路 |
|---|---|---|
| AnimatedContent / Visibility / Transition | 状态、辅助工具栏、短段内容切换 | 引入对应 AndroidX 包并编译原型；不包住整个 TextField 或大列表 |
| Animatable / spring | 手势停靠、可打断形变、单一焦点 | remember 持有，事件/受控 Effect 发起；主服务状态不由动画结束回调推进 |
| graphicsLayer / drawWithCache / DrawScope | 局部变换、关联轨迹、轻图形 | 晚读动画值；Path/Brush 缓存，避免每帧重组整页/分配对象 |
| SharedTransitionLayout / sharedBounds | 记录→详情、提案→事实的视觉连续性 | 相同 typed identity，实际 1.11.3 编译/标注核验；懒列表回收、Back、IME、焦点、双栏均测；退为常规转场 |
| 自定义 Layout / 手势 | 日期定位、金额对齐、局部展开 | 先证实普通布局不能完成；不每帧全列表 measure，不抢系统 Back/滚动手势 |
| M3 Expressive public 组件 | 合适的选择/动作/指示器 | 当前 1.4 缺 public API 时用基础 public API 表达设计；1.5 beta 升级仅独立实验，不默认入主线 |
| AndroidX graphics-shapes | 必要的复杂形态插值 | 先比较自绘简单形状与额外依赖收益；不为一个装饰图形引通用形态框架 |
| RuntimeShader / AGSL | 小面积、短时 Agent 光学标识或任务态材质 | API33+；本项目 min34 已满足，仍需 GPU/热/生命周期与减少动画测试；实色或静态 Brush 退路 |
| RenderEffect | 有意义的局部模糊/离屏效果 | API31+；min34 已满足；不误把 layer blur 当任意 backdrop blur，读回/离屏成本需实际测量 |

AGSL/RenderEffect 的系统门槛不是本项目的主要障碍，**真实收益、GPU 填充/离屏层和持续耗电才是**。不借此支持 minSdk 以下版本或新增重型渲染依赖。[AGSL 官方说明](https://developer.android.com/develop/ui/views/graphics/agsl)、[RenderEffect API](https://developer.android.com/reference/android/graphics/RenderEffect)

自绘页面保持普通 semantics/可见动作。工程起步仍在 `:app` 内按业务包划分 `ui/theme`、`ui/components`、`ui/timeline`、`ui/finance`、`ui/notes`、`ui/agent`；这里只是候选文件责任，不预建多模块/通用 Design Engine。UI 经现有 Application Services 工作，Room/Koog 不为视觉改模型。

每个实验先固定数据集、可见流程、设备温度/电源状态、刷新率、构建变体及 shader 编译预热条件。分别观察首次运行与暖态，不以 Debug Layout Inspector 的结果宣称 Release 体验。

- 主线程点击/输入可见反馈目标 ≤100ms；保存由实际 I/O 完成，不人为等待动画。
- 记录 60Hz/120Hz 对应 16.67/8.33ms 帧预算的实际 deadline miss、P50/P95/P99 和长帧；候选目标稳定流程 jank <1%，不把平均 FPS 当通过。
- 对比 1k/10k 合成混合记录、长 Note、展开/收起与连续分页；容量是测量夹具，不修改产品限制。用 Perfetto/Macrobenchmark 或当前批准工具采集，不为本轮安装技能擅自加 benchmark 模块。
- 单个视觉效果内存、GPU 与能耗报告相对基线增量；候选内存增量预算 ≤10MB，超过需证明收益；idle/隐藏后停止效果的额外帧/循环，连续操作 10 分钟观察热和性能漂移。
- Shader 限定绘制面积、无复杂采样/大半径全屏模糊；记录 FrameTimeline/GPU 与掉帧。减少动画与实色退路必须同样能完成任务。

[Compose phases/performance](https://developer.android.com/develop/ui/compose/performance/phases)说明重组、布局与绘制可分别跳过；因此优化看实际阶段成本，不给所有对象加稳定性注解。[Shared element 官方说明](https://developer.android.com/develop/ui/compose/animation/shared-elements)用于选择共享内容，不证明本项目集成已通过。

### 12.2 展开的 AI 对话 S2

由底部入口展开接近全高的 N 式消息面板，承接完整 Note 正文、完整收支字段、用户消息、真实引用和 Agent 结果。保持 D 的主美术语言，不把 N 的海景作为必需资产。输入区只有一个自然语言 composer，**没有“记账 / 笔记 / 问 AI”模式切换**。

用户可自然表达记账、记录笔记、查询、归纳、建立/解除关联等意图；Agent 通过既有 Tools/Services 准备结果。Answer / Navigate / ClarificationNeeded / ProposalReady 继续是四种真实输出，统一输入不抹去其语义差异。涉及业务写入时，“待确认/尚未写入”与检查原生提案的动作清楚可见，不能让发送消息等价于提交。

完整内容指当前会话和所需/引用记录的完整可读展示，不代表打开输入栏就默认整库上传或后台扫描。无授权/无 Key/无 AI 时，对话可解释状态并提供既有启用/配置流程，顶部两个手动入口继续可用。收起不取消 Run；恢复会话、停止、撤销、Interrupted、未知提交等按既有合同处理。

### 12.4 配套页面的具体设计方案

**手动记账。** 从标题旁“记账”进入独立原生页，不穿过 Agent。延续黑白账页：顶栏返回/“记账”，支出收入选择、金额为首要焦点；发生时间、日常账户、可选分类、说明使用有明确行边界的字段组；底部黑色“保存记录”主动作。输入由原生 IME 优先承担，自定义数字面板只有验证确有收益才采用。草稿状态与正式保存分开；失败/冲突保留输入，未知结果核查时不显示成功或制造第二笔。完成后回原首页位置，只有持久事实进入摘要。

**手动笔记。** 从“笔记”进入以正文为主的编辑页，不要求先命名或与 AI 对话。顶栏日期/完成编辑，正文按 16sp 起始、24sp 行距自然排版，保存状态位于工具栏固定语义位置；输入不被入场动画重建，500ms 停输、冲突保留及软删除按现有编辑状态。阅读态突出正文与下方关联收支；朱红只强调可操作关联，正文不套黑色聊天气泡。首页的主题为正文首句/摘要，不能反向成为第二套标题字段。

**原生提案确认。** 从 S2 的“检查提案”进入，顶栏“检查提案/编辑提案”，顶部固定可读“待确认，尚未写入记录”。各操作用同一账页字体系分别呈现金额、正文和关联两端，完整原文可展开阅读；底部唯一提交动作“确认并保存”。新增/修改/关联的数量和影响范围明确，当前版本检查仍归业务服务，界面不展示原始数据库标识。只有 Applied 才转换为成功记录入口；Pending、未知、版本冲突、授权撤销均保留其真实含义。

**跨页共同规则。** S1 摘要、原生详情、S2 引用与确认页对同一对象使用一致金额/正文、时间和业务身份，避免每一页编出另一套标题。输入、滚动和来源锚点由对应 owner 保留；手动入口不依赖 AI，收起会话不取消 Run。下一轮具体图稿优先覆盖这三个任务，再补深色、IME、大字号和失败/冲突状态；以现有 S1/S2 延伸，不重新发散美术方向。

## 13. 最新产品变更：明确指令直接执行

### 13.1 用户体验与决策

本节为 Plan §30.1 新要求的具体变更设计。主流程改为 **用户表达意图 → 本地解析/校验 → 执行 → 结果回执**，不要求用户读内部结构化提案，也不在每次聊天中增加“是否确认”。内部需要准备/冻结操作，不等于用户必须看一个名为 Proposal 的页面。

| 用户输入 / 状态 | 新交互目标 |
|---|---|
| “午饭58元”且当前语境足够明确 | 直接新增对应支出；回执显示真实金额、发生时间及必要字段，可点开原生详情 |
| “记下：明天和同学讨论项目” | 按原文创建 Note，不扩写正文；必要发生日期歧义按时间合同处理 |
| “把这笔午饭和项目讨论关联起来”且上下文各有唯一目标 | 直接关联；回执显示两个真实对象的关系 |
| “午饭花了多少钱？” | 只查询，不因提到金额就写入 |
| “把那笔改一下”或有多个同名候选 | 在原对话补问缺失的对象/数值；不做笼统的全量确认页 |
| 对象/版本在处理时发生变化、已删除、授权失效 | 停止该次写入并说明真实问题；不静默采用新版本覆盖或复活对象 |
| 网络重试、重复工具调用、提交回执未知 | 按稳定请求/operation 身份核查；不重复创建，也不把未知展示为失败后再新建 |

日常写入范围仍以既有六类操作为评估起点：新增/修改收支、新增/修改 Note、关联/解除关联；不能把取消确认理解为开放删除、恢复、任意 SQL/文件/网络命令。需要授权/凭据时保持明确的首次启用与 Provider 机制，不把“少一次确认”扩为静默外发。

### 13.2 T1 结果反馈

保持 S1 的手动入口和底部统一 Agent 入口；对话继承 S2 的完整内容、消息节奏与黑白朱红语言。旧“已准备，请确认”改为真实执行完成后的短回执，例如“已把午饭与项目讨论关联”，下方显示关联对象及“查看记录/更正”。回执与持久 Operation/记录身份绑定，不能直接采信模型一句“完成”。

仍需区分执行中、补问、成功、确定性拒绝、结果未知、Interrupted。没有进入数据库的推理/准备不显示已保存；失败不显示空记录。收起不取消 Run，用户主动停止是否来得及中止写入必须按真正事务边界解释，不能假称已经提交的操作被撤回。

不默认提供通用“撤销”按钮。现有 CommitOperation 没有通用的完整修改前快照，UPDATE payload 也不能证明具有原字段；创建交易亦无已开放通用删除操作。更正可以是新的明确修改请求或原生编辑流程，保留历史和版本校验。以后若需要真正 undo，应单独设计可逆性、原值/关系快照、并发和补偿原子性，再评估 Schema/备份/迁移影响，不能让模型猜旧值。

### 13.3 最小技术路径建议与权威变更清单

优先评估保留内部结构化 prepare、revision CAS、不可变 operation、短事务 A/B、稳定身份/幂等、原子提交和结果核查，只把**执行授权来源**从“展示 payload 后用户再次确认”改成“当前真实用户消息表达的明确操作请求，并通过本地执行策略检查”。这会改变现有 A 的前置条件，必须明文修改，不能伪造 native-confirm receipt 或绕过检查。

模型仍不获得原始 Room/SQL 或通用 commit 能力。建议由 Record 的本地 Coordinator/执行服务在本次主动请求内协调冻结与提交；Koog 的职责仍为受控推理/Tools。是否保留内部 Proposal 名称/四输出、如何持久关联用户消息与执行授权、执行回执与消息结果的编码，要在正式接口设计中一起决定，不在视觉稿里假定兼容问题不存在。

| owner / 来源 | 正式实施前须同步的内容 |
|---|---|
| [冻结架构 §5–6](../architecture/record2-v1-unified-architecture.md) | 当前明确要求用户确认后创建 Pending；需补当前指令授权、自动执行调用点及来源边界 |
| [Spec §4.2 / §5.4](../specs/record2/v1/spec.md) | Transaction A 前置条件、ProposalReady 交接、澄清/冲突及真实结果输出；原验收条款不能继续假称没变 |
| C1 / D1 / F2 | 提交服务与编排的权限、工具结果到执行的衔接、去独立确认页及一致结果渲染 |
| E1 / E2 | 权威消息/Run 与 Operation 的完成先后、取消/撤销/迟到结果；模型回复不能抢先声明业务成功 |
| G0 / G1 / G2 | 已执行/处理中状态的备份恢复、旧 Pending 隔离、操作来历与跨版本格式；新增授权来源不能使旧数据自动获执行资格 |
| 测试与执行范围 | 明确目标/金额、问句零写入、多目标补问、Prompt injection 零权限提升、CAS、重复/取消/进程终止/回执未知和恢复；按变更后 AC 建真实证据 |

主要风险是取消逐次复核后，错误理解可能直接成为本地业务事实；降低风险的手段是明确用户意图、唯一对象、确定性字段校验、完整结果回执和可更正路径，而不是保留一个用户不愿看的技术提案页。本轮已完成体验方案与静态候选，未修改正式 Spec/架构/AC、Kotlin、Schema 或并行任务实现，不能将该方向记录为已运行的自动执行能力。

### 13.4 自主裁决优先，补问只解决必要缺口

Agent 应先在预算内利用当前指令、明确引用/焦点、会话上下文、正常可见记录和已约定默认值完成判断，不把每一次内部不确定都转给用户。是否补问看缺口是否会实质改变业务结果，而不是模型是否能做到绝对确定。

- CNY、既有默认账户、可选分类等已有规则足以解决时直接使用；分类不明确且允许为空时留空，不为此停下。发生时间采用正式约定的默认规则，不由模型随意编造；“笔记正文提到明天”不自动等于 Note 发生时间在未来。
- “这笔/刚才那条”已有明确当前对象时直接沿用，不再让用户点选同一对象；先查已有信息，不让用户重复报账户、日期、原文和已知金额。
- 对分类/展示摘要等低影响决策可自主选择。不能为少问而捏造金额、混淆修改对象、猜缺失正文或把查询当写入；不能以内容中的指令提升执行权限。
- 必须补问时，只解决当前阻塞执行的最小问题；用一条短回复能补齐两个紧密相关的必要值时合并，不机械拆成多轮字段问卷。通常一问足够，不设置“问满一次后必须猜”的硬上限。
- 默认只显示一句直接问题，至多 2–3 个短候选；可用点选、一个数字或短句回答。没有相关候选就只留一个短输入，不堆原因说明、技术术语、字段表格或确认摘要。
- 回复只补缺失值，保留用户原指令和已知参数；例如用户只点“昨天午饭”，金额 68 已在原任务中，不再追问金额、完整日期或是否继续。

| 场景 | 补问 / 自主处理 |
|---|---|
| 用户“午饭58元”，账户/币种有默认规则 | 直接记录；不问“确认支出？账户？分类？” |
| 用户“记录午饭”，缺金额 | “午饭多少钱？”可直接回“58” |
| 用户“那笔改成68”，没有当前唯一对象 | “改哪笔？”展示两个相关短候选 |
| 用户“午饭改成68”，同名且没有可靠焦点 | “改哪笔午饭？”选“今天 · ¥58 / 昨天 · ¥42” |
| 用户“记一笔”，主题和金额都没有 | “记什么、多少钱？如‘咖啡18’。”不展开完整表单 |
| 用户“记下：明天讨论项目” | 保存这段原文；不为正文内容额外问 Note 的发生时间 |

回执也要简洁：展示已经完成的实际动作和关键结果，不长篇讲推理过程、风险或默认字段清单。用户可以直接更正，Agent 在明确作用对象后处理；没有必要再问“你确定要更正吗”。

### 13.5 主区域是 Agent 工作区，必要问题用弹窗

保留 N 式展开面板与统一输入的易用性，主区域以**完整记录对象、必要上下文、本次指令和执行结果**为中心，不模拟一位真人反复聊天。普通成功用结构化回执表达，不重复“我已为您……”长文；输入仍支持自然语言，也能查看必要会话/操作历史。

必要补问采用一个紧凑的任务弹窗，问题直接作标题；可选时每个选项自身就是答案，点击后继续当前任务，不再加“下一步/确认”按钮。需要金额等自由输入时只显示单个字段和明确的继续动作。正文、候选数量、可点击面积按原生无障碍要求处理，不能为了“小”把文字和目标压缩。

弹窗只针对当前前台主动请求出现，不因后台/迟到结果反复抢焦点；一次只有一个，不堆叠、不再打开第二层确认。底层记录区保持原位置，已有输入/任务参数保留；用户关闭或返回则暂停/放弃这一待补充操作，不写猜测值、不再次弹出追问，可从原任务入口继续。其余无依赖读取可继续，不能用一个问题锁死整个 App。

问题和简短答案不以新的聊天气泡挤进主工作区，也不误存为 Note 或收支。必要来源/回复仍按正式 Session/Run 合同保存并可在任务详情中查看；减少视觉干扰不等于删除权威消息。提问结束当前需要用户输入的 Run，再如何把补充值交给后续主动执行由正式 Coordinator/历史接缝设计；不让 Koog 在长运行中等待一个 Dialog。

例：用户“把午饭改成68元”，存在两笔同名且没有可靠焦点。弹窗仅显示“改哪笔午饭？”、两个候选“今天 · ¥58.00”“昨天 · ¥42.00”，可附一行简短上下文“改为 ¥68.00”。选中后沿用原金额意图、重验对象版本并继续，关闭则不执行修改。整个过程不向主区追加一串问题、答案和再确认。
