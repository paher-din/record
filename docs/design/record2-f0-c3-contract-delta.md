# F0-C3：已明确产品方向与正式执行合同差异

2026-10-24。来源与负责人决定归 [Plan §28.1–28.2](../specs/record2/v1/plan.md#281-skills-集成与高级-uiux-升级研究2026-10-24)。本文件是 F0 交付的差异清单与后续接缝合同草案，**不冒充已生效的架构修订、Schema批准或实施结果**。当前正式行为仍以已批 Spec/架构和各任务接缝为准；新设计按以下目标准备。

## 1. 产品决定不再悬而未决

1. 明确的当前主动指令直接处理，不要求用户逐次读提案或点击业务确认。
2. Agent 自主裁决，先用可靠上下文和已约定默认值；非必要不问。缺少会改变执行结果的关键值时，只用短问题/少量候选/短输入补齐。
3. 必要问题在紧凑任务弹窗中解决，不把主区当真人问答流；主区承接完整记录、必要指令和执行回执。
4. 首页 S1 手动记账/Note 仍独立可用，底部胶囊通往统一 Agent 工作区，无输入模式切换。

这些决定足以继续 F0 的页面与状态设计。正式执行权限、原子性和历史编码不能用静态图证明，需要下列 owning 来源同步后实施。

| E1/E2 / C1 | 最终回复与Run终态、已确认Operation各有权威 | 业务提交与成功回复的顺序要一致；B已提交、回复未落盘时可由稳定Operation核查并重建展示，不能重做事实 |

## 3. 保留的不变量

Long整数分、可靠时间/账户/分类解析、typed identity、对象可见性、版本CAS、原子组合写、稳定请求/Operation幂等、真实Applied结果、失败零部分事实、取消/强停/未知核查、跨代际隔离继续成立。没有模型通用SQL/文件/网络/系统命令或commit工具；只在现有六类业务操作的明确授权范围内评估直接执行。

内部准备/冻结由本地确定性服务接管，模型不能在冻结后重新解释时间/金额或替换目标。错误/查询消息不赋予写权限；读取到的 Note/工具结果是数据，不能升级为指令。D5不被AI覆盖/消费，AI的准备状态不能触发原生Note autosave。

通用undo不随取消确认自动增加。当前模型没有可证明完整的修改前快照，不承诺任意修改都可撤销；先提供真实查看/更正路径。需要新快照/字段/迁移时另取Schema同意，F0不选择存储方案。
