## 1. 设计目标与范围

面向日常使用手机记录收支与纯文本笔记的个人用户。在明亮环境快速记账，在弱光环境阅读或补记；浅深色均为完整主题，采用负责人指定色值。整体以连续时间线串联事实，通过双向关联连接笔记与收支；AI 作为可关闭的辅助入口，所有业务写入仍回到原生确认。

本轮只交付设计合同与合成数据候选，不改正式 App Host、Schema、业务服务或设备。冻结行为来自 [Spec §4–6](../specs/record2/v1/spec.md)、[决策来源基线](../product/record2-v1-decision-baseline.md)与 [B0 数据设计](../architecture/record2-b0-data-model-design.md)。不新增统计大盘、搜索中心、账户余额、P1 页面或系统悬浮窗。

## 2. D-SYS：主题、文字与共享组件

### 2.1 负责人指定的基础色

色值精确采用 sRGB Hex，不经动态取色、品牌色生成或 Material 默认主题改写。

| 语义 token | 浅色 / RGB | 深色 / RGB | 用途 |
|---|---|---|---|
| `page` | `#F5F5F7` / 245,245,247 | `#000000` / 0,0,0 | 页面底色、内容间留白 |
| `surface` | `#FFFFFF` / 255,255,255 | `#1D1D1F` / 29,29,31 | 内容分区、编辑区、面板、对话框 |
| `brand` | `#0071E3` / 0,113,227 | `#0071E3` / 0,113,227 | 主按钮、选中控件、角色主体 |
| `accent` | `#FF9F0A` / 255,159,10 | `#FF9F0A` / 255,159,10 | 待确认、未保存、失败提示标识 |
| `positive` | `#34C759` / 52,199,89 | `#34C759` / 52,199,89 | 已完成/已保存状态标识 |
| `textPrimary` | `#1D1D1F` / 29,29,31 | `#FFFFFF` / 255,255,255 | 标题、正文、金额、操作名称 |
| `textSecondary` | `#6E6E73` / 110,110,115 | `#86868B` / 134,134,139 | 日期、辅助文字、说明、占位文字 |

候选补充规则：主按钮 `onBrand=#FFFFFF`；橙/绿色实底标识 `onAccent=#1D1D1F`。分隔线可由当前主题的 `textSecondary` 取 20% alpha，纯装饰用途；重要输入边界、焦点和选中不能只靠低对比分隔线。默认跟随系统，并在设置中提供“跟随系统 / 浅色 / 深色”；这项切换交互待批准。

### 2.2 对比度与使用限制

采用 WCAG 相对亮度公式计算无透明度的 sRGB 色对，普通文字目标 ≥4.5:1，大字与必要非文字标识 ≥3:1。这里只证明色对，不代表整页可访问性已通过。

| 前景 / 背景 | 比值 | 设计约束 |
|---|---:|---|
| 浅色主文字 / 页面 | 15.46:1 | 正文可用 |
| 浅色次文字 / 页面；白色分区 | 4.66:1；5.07:1 | 辅助小字可用，不再降低透明度 |
| 深色主文字 / 页面 | 21.00:1 | 正文可用 |
| 深色次文字 / 页面；深色分区 | 5.80:1；4.64:1 | 辅助小字可用，不再降低透明度 |
| 白色 / 品牌蓝 | 4.70:1 | 主按钮文字可用 |
| 品牌蓝 / 浅色页面；深色分区 | 4.31:1；3.58:1 | 不作这些底色上的普通小字；链接用主文字加下划线，选中用蓝底白字 |
| 橙色；绿色 / 白色分区 | 2.06:1；2.22:1 | 不作小字、细线图标或唯一状态标识 |
| 近黑色 / 橙色；绿色 | 8.19:1；7.58:1 | 彩色实底状态标签使用近黑字，并写明状态 |

不把蓝色改浅、灰色改深来绕过负责人色值。错误用明确标题、原因、恢复动作和橙色标识，不自行增加未批准的红/紫色。收入/支出始终有文字和正负号，颜色不承担唯一语义。

### 2.3 文字、布局、图标与动效候选

- Android 系统 sans-serif，中文使用系统字形，不仿造 iOS 系统字体，不下载字体。标题 28sp/34sp、分区标题 20sp/28sp、正文/输入 16sp/24sp、辅助文字 14sp/20sp；金额 40sp/48sp，中等字重、等宽数字。字号跟随系统，不锁定行高或容器高度。
- 页面横向间距 20dp；窄窗口 16dp；节间距 24dp；行内 8/12dp。内容分区圆角 16dp、输入/按钮 12dp。只在有内容边界时使用分区，不逐层套卡片、不加装饰渐变或玻璃效果。
- 主要触控目标至少 48dp，保留可见文字；图标使用同一套 Android Material Symbols Outlined，24dp，语义来自动作。候选稿优先显示文字按钮，不把临时字符当最终图标资源；正式资产选择属于 D-SYS 审批。
- 紧凑窗口单列；≥600dp 两栏列表/详情候选，编辑区宽度上限 640dp；≥840dp 面板最大宽度 560dp。折叠/旋转前后保留目的地、输入、光标、滚动、提案和 Run；不以屏幕方向决定布局。
- 页面转场 180ms 淡入/位移、Bottom Sheet 240ms ease-out、角色贴边 180ms ease-out；禁用动画时即时切换，不呼吸、不弹跳、不循环打扰。保存成功只用文字/状态更新，角色表情不证明保存成功。
- 系统栏随主题，edge-to-edge 使用实际 insets。IME 出现时编辑操作可达、角色避让；大字体重排按钮，屏幕阅读器读出金额方向、日期、保存状态、关联数量、错误与动作。状态改变通过公告而非抢焦点。

共享组件候选：`RecordTheme`、`RecordPage`、`RecordAction`、`StatusLabel`、`RecordRow`、`MoneyInput`、`SaveStatus`、`LinkSelectionRow`、`ConfirmationSheet`。按业务需要复用，不为 F0 创建组件源码或通用框架。

## 3. D-TIME：单首页、详情与双向关联

**首页候选。** 顶部“记录”、日期跳转和“设置”；下一行“全部 / 收支 / 笔记”筛选。连续时间线按日分组，以发生时间倒序，类型、摘要、金额、时间和关联数量构成一条可点记录。下方两个明确动作“记账 / 写笔记”，AI 角色贴边且不遮挡动作。日期跳转只定位连续列表，不能退成单日列表。

点击详情保留原日期锚点、筛选和滚动。支出示例“午饭 −¥58.00”，收入“兼职 +¥200.00”，笔记“和同学讨论课程项目”；同日混排，不以两种卡片高度暗示重要性。笔记正文不自动生成新的标题字段，时间线仅展示原文摘要。

**详情候选。** 收支详情优先呈现金额/方向，其次发生日期、账户、分类、说明，再列关联笔记；笔记阅读态呈现完整正文和关联收支。关联条目点开对端，返回回原位置。

**关联选择。** 标题“关联笔记”或“关联收支”；说明“更改尚未保存”；每行独立勾选和“查看”，底部“保存关联”。“查看”只读，返回保留选择。候选列表只含正常可见目标，隐藏关系不进入取消集合。保存前对端变化则整批失败并保留选择，展示“记录已变化，请重新加载后确认”；不得部分成功。无变化直接返回，有变化返回时提供“继续选择 / 放弃本次更改”。

| 状态 | 表现与动作 |
|---|---|
| 初次加载 / 翻页 | 标明“正在加载记录 / 正在加载更多”，不伪造记录；翻页失败保留已有列表和“重试” |
| 无记录 / 筛选无结果 | 分别“还没有记录，记下第一件事”及“此筛选下没有记录”，保留创建或清除筛选入口 |
| 读取失败 | 明确“记录加载失败”，重试；不把失败展示为空 |
| 关联冲突 / 提交中 | 保留未提交选择；冲突重读并重新确认；提交中锁重复与离开 |
| 长文 / 大金额 / 大字体 | 摘要可截断但详情完整；金额不缩到不可读，改行；动作自然换行 |

## 4. D-FIN：记账、编辑与 D5 草稿

新建/编辑使用同一结构：标题 → 收入/支出选择 → CNY 金额输入 → 发生时间 → 账户“默认账户” → 可选分类 → 说明 → “保存记录 / 保存修改”。金额是十进制原始文本，校验提示贴近输入；无计算器、余额和未冻结的统计模块。

保存前不让时间线显示为正式事实。保存中按钮写“正在保存”，阻止重复和离开；结果未知显示“正在核查保存结果”，先按稳定身份核查，不能直接新建第二笔。失败保留全部输入；版本冲突保留本地内容，提供“查看最新记录”，重新审核后再保存，不自动套最新版本。

草稿持久化状态与交易保存状态分开。进入时发现 D5 提供“继续草稿 / 显式放弃草稿”；改变后 Back 先收 IME，再提供“继续编辑 / 保留草稿并离开 / 放弃输入”。保留失败必须停留并写明“草稿尚未保存”，不能以关闭弹层冒充保存成功。成功记录与草稿消费一致。

状态覆盖：初始、金额不合法、未来时间拒绝、未保存、草稿保存中/失败/已保留、记录保存中/失败/结果未知/成功、旧版本冲突。取消只关闭未提交编辑流程，不能取消已经进入不可中断提交的事务。

## 5. D-NOTE：阅读、自动保存与软删除

已有 Note 默认阅读态，新建直接编辑。编辑页只展示发生日期、纯文本编辑区和真实保存状态，不新增标题或 Markdown 渲染。正文保留中文、空格、换行和符号；“完成编辑”只离开编辑，不承担第二套保存语义。

| 状态 | 文案与行为 |
|---|---|
| 新建空白 | “写下此刻的想法”；不创建事实，可直接返回 |
| 输入 / 500ms 停输 | “尚未保存” → “正在保存”；只串行保存最新输入版本 |
| 当前版本已提交 | “已保存”；旧回执不能使新文本变为已保存 |
| 保存失败 | “保存失败，输入仍保留”；“重试保存 / 继续编辑”；退出必须明确放弃未保存修改 |
| 清空既有正文 | “正文不能为空，原记录尚未改动”；可继续输入或恢复上次正文，绝不隐式删除 |
| CAS 冲突 | 保留本地文本和只读最新正文供比对；“查看最新内容”，不静默替换缓冲或覆盖远端 |
| 已被删除 | 停止编辑并显示“笔记已删除”；返回或进入专用恢复入口，不由旧 autosave 复活 |

阅读态“更多 → 删除笔记”确认：“笔记将从时间线及关联列表隐藏，可在已删除笔记中恢复”；取消零变化。成功后回原时间线，显示“笔记已删除 / 撤销”。设置中的“数据与备份 → 已删除笔记”提供列表、只读预览和“恢复笔记”，显示原日期与删除时间。恢复后沿用同一身份、原发生时间和原关系，不置顶、不新增副本。删除和恢复提交中拦截重复/离开；失败维持原状态，可重试。

## 6. D-AI：抽象角色、聊天与原生提案

### 6.1 角色和面板

蓝色圆形主体，两个克制的白色眼点；不借用人物/吉祥物资产。Idle 静态，Running 用文字状态“处理中”，NeedsInput 显示“待补充”，PendingConfirmation 显示“待确认”，Error 显示“需要处理”。状态使用本地权威状态，不从模型措辞推断。

角色可拖动并贴边，点击打开应用内 Bottom Sheet。通过面板“隐藏助手”隐藏，通过首页的“显示助手”次级入口恢复；屏幕阅读器/键盘有“移到左侧 / 移到右侧 / 隐藏”操作，不要求完成拖动。位置约束到实际安全区，避让 IME、底部主按钮、系统对话框、恢复门禁与不可中断提交。

Sheet 顶部为会话名称、“会话历史”和“收起”；中间是用户可见消息及真实记录引用，底部为输入/发送。运行时展示“停止生成”，收起/业务导航不停止 Run。初始 AI 未启用时展示“启用 AI”，不能借点击角色静默同意外发。

### 6.2 四种结果与原生交接

| 类型 | 候选呈现 | 必须保持的行为 |
|---|---|---|
| `Answer` | 回答正文、可点记录引用与数据覆盖范围 | 引用打开真实记录；回答不代表业务已提交 |
| `Navigate` | “查看这条记录”或进入目标记录 | typed identity 重新校验；失效明确说明，不执行模型 route |
| `ClarificationNeeded` | 显式问题及输入区 | 不猜日期/金额/对象，不形成已冻结提交 |
| `ProposalReady` | “待确认，尚未写入记录”和“检查提案” | 打开原生确认页，聊天不增加一次二次确认 |

提案页按操作顺序展示“新增支出 ¥58.00 / 新增笔记 / 关联两条记录”，明示时间、账户/可选分类、原文和既有对象。展示当前 revision；“编辑提案”只改 Proposal，不启动原生 Note autosave、不消费 D5。底部唯一提交动作“确认并保存”，按当前展示版本走 A/B。

原生 D5 同时存在时给出“继续原生草稿 / 保留原生草稿并处理提案 / 显式放弃原生草稿后处理提案”，不静默覆盖。提交中锁重复和离开；未知结果“正在核查提交结果”，先查询 operationId；只有持久 Applied 才显示“已保存 / 查看记录”。旧 revision、目标变化/删除、旧代际拒绝时保留提案并要求重新审核，不复活笔记。关闭未确认页保留提案，不提交。

状态覆盖：未启用、缺凭据、就绪、Running、待补充、待确认、请求失败、Interrupted、授权撤销、提案冲突、结果未知、Applied、D5 冲突。错误区说明动作和保留内容，不自动重试模型或 Pending。

## 7. D-SAFE：设置、授权、历史与备份恢复

设置使用分组列表：“外观”“AI 助手”“会话历史”“数据与备份”。AI 模式只有“无 AI / 完整 AI”；Key 缺失/断网/额度不足为状态，不增加模式。关闭 AI 不默认清历史/Key，也不声称收回已发送数据。

**授权页候选。** 显示实际 Provider / 接收方与当前 E0 catalog 一致的服务身份；明确“主动任务按需发送正常可见记录和必要历史，不默认整库上传或后台扫描”。“同意并启用 / 暂不启用”分明；Provider 变化需要重新授权。凭据输入使用隐藏文本、关闭建议/自动纠错，不回显真实 Key；设计稿不含真实秘密。Key 不进聊天、备份或普通库；网络错误不提供自动删 Key 的反馈。

**历史列表候选。** 会话标题、最后消息摘要、时间、Interrupted/待确认标识，选择后打开同一会话。删除前明确说明：删除可见聊天与未确认提案、停止当前 Run；不会删除已生成的正式记录；为核查已确认提交保留必要依据。Pending 无法安全保留时阻止删除并要求先核查，不能级联丢失依据。

**数据与备份候选。** 三个入口“导出完整备份 / 从备份恢复 / 已删除笔记”。导出前告知 ZIP 未加密，包含私人笔记、已删除记录、隐藏关系和 AI 对话，不含 Key/有效授权；原生草稿按 G0 最终合同明确处理，本稿不选备份格式/阈值或草稿段方案。

恢复路径为：系统选文件 → 有界校验中 → 已验证候选摘要 → 整体替换确认 → 恢复中 → 重开并核查结果。确认页显示实际候选的来源/范围/数量与“将整体替换当前数据”，取消保持原数据。选择字节变化必须重验。隔离导入/切换/回退阶段的可取消点由 G0 协议确定；不可中断阶段锁定返回，不能伪称取消成功。失败只显示真实可读的完整旧数据或已验证完整恢复结果，安全性由 G1 证明。

恢复后的 AI 提示“历史可阅读，需重新授权并配置凭据”；旧 Running 不续跑，旧 Pending 不执行，未确认提案重新审核。恢复笔记与整体恢复分别命名，避免误操作。

## 8. 审阅稿覆盖与批准清单

| 设计组 | 候选页面 / 关键状态 | 本次需负责人审阅 |
|---|---|---|
| D-SYS | 所有页面两主题；可读性与共享组件规则 | 字体/字号、间距/圆角、图标体系、系统主题选择、动效及大屏规则 |
