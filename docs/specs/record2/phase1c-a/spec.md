## 5. 数据和原子性契约

物理字段/新库范围由 [Plan §4](plan.md#4-新实验数据库与写入范围待批准) 提交批准；以下是必须保持的行为：

- 金额直接从十进制文本精确转为正 Long 分。拒绝零、负数、溢出、超过两位小数、指数和分组分隔符；编辑回显与展示也不得通过 Float/Double 计算金额。
- C1/C2 同标准：首次 Room 打开前确定并冻结 runId、候选身份与规范化库路径；Application/自动初始化不得先开默认库。真实 Activity、Repository、Instrumentation 和独立 SQLite 观察器均核对实际连接对应同一身份；缺失/冲突立即停止，verify/重启不能创建空库补救。具体顺序见 Plan §4.3。
- 一笔收支全部字段一次落盘，保存成功与消费该草稿一致完成；重复保存/重试以同一稳定身份协调，不能多一条。未知结果先重读，不盲目再插入。
- 新建交易在首次提交前生成稳定身份并保存到同一编辑草稿；C1 的交易 id、C2 的 recordKey 均跨失败/重启重试保持不变，不能依赖提交成功回执才记住身份；C2 自增主键只是同一 recordKey 的物理映射。
- Note 首次非空保存后即为正式事实；空白新建不入库，清空旧正文不改库；较早回执不能覆盖最新正文或假报最新版本已保存。
- 链接端点存在、同一对唯一、批量增减原子提交；取消无变化，解除不删正文/收支。
- 发生时刻为排序和日期分组依据；不以修改时间置顶。同刻按稳定身份确定顺序；A 跑同日/前一日基本路径，完整午夜/DST/分页边界留 B。
- Timeline 是查询投影，草稿不是真实流水；仅候选App自己的合成磁盘库可写，不能用Instrumentation临时库替代。新实验不迁移任何旧库，不使用 destructive migration/fallback。

## 7. 对称评价、完成与停止

- 已批准预算：公共准备最多 1h；每候选 8 个有效工程小时（1h 准备、4h 业务、1h 最小安全、1h 可行性/依赖、1h 证据）。是探索上限，不是交期或可降低验收的理由。
- 两候选用共同逻辑断言和相同目标，允许物理主键/适配器差异；继承代码、保留依赖、去依赖、Fork 修补、验证返工都计成本。不只比较净新增行数，不把待做 B 算成零。
- 记录 PASS / FAIL / BLOCKED / INCOMPLETE / NOT RUN；达到预算就提交实际状态并停止，不追加未获批工作。候选失败不隐藏，既定独立 C2 比较不以 C1 成功为前提；对已证伪假设的重试或目标变更另走项目修订/重新批准规则，不自动创建或覆盖 ADR。
- **实验执行收口：** 两候选在批准预算/协议内完成探索或按停止条件终止，六项逐项保留实际结果（未跑标 NOT RUN 并说明原因）、命令/失败原证据、成本/风险和终态，且主代理完成保护/证据接受后，可按既有生命周期将本实验 Spec 标 `completed`；不要求至少一个候选通过。协议越界、证据缺失或应做的失败处理未完成，不能收口；本轮仍是 draft。
- **候选通过与选型：** 某候选只有完整通过 A-AC1～6 才具备提交选型的资格；Spec completed 不会把候选 FAIL/BLOCKED/INCOMPLETE/NOT RUN 改成 PASS。两者均未通过时，实验结果必须写“无合格候选”，不得宣布选型成功或选择不合格基座；成本接近则“无法区分/需补证”。最终基座仍由负责人确认。
- 正式 Record 2.0 产品开发须另建 Spec/Plan，完整保留 B-AC1～9 和 BK1～5；本 Spec 不允许以“原型已运行”为由跨过正式日用安全门槛。
